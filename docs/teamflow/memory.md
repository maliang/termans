# termans · TeamFlow 跨需求约定

## 约定
- **AI 供应商配置的交互基线**（20261030-r1 起）：新建供应商必须支持「未保存即读取模型列表」（草稿配置走 `ai:list-models` 的可选字段），模型必须以可点选清单呈现且保留手输入口 —— 不允许再退回「先保存再读取」或纯 `<datalist>` 自动补全。
- **默认思考强度**（20261030-r1 起）：全局单一存储位 `settings.ai.reasoningEffort`，固定三档 `low | medium | high`；三档到各协议原生参数的映射只允许存在一处实现 —— 住在 `src/shared/reasoning.ts`（渲染层与主进程共用一份），`src/main/ai/adapters.ts` 只调用它、不再写第二份数字/白名单；并由单测穷举 4 协议 × 3 档。UI 只呈现三档，不暴露 `reasoning_effort` / `budget_tokens` 等原始参数名。
- **AI 设置页的形态基线**（20261030-r2 起）：供应商配置一律「单列卡片 + 卡片内联展开编辑」（内容列 `max-width: 720px`），新增供应商走 `catalog`（预设目录）/ `custom`（手填）双模式；卡片行摘要固定为「名称 · 当前模型 · key 尾 4 位 · 默认徽标 · 凭据状态圆点 · 行尾操作（编辑/删除/设为默认）」。不允许回退成「列表 + 下方单栏表单」、弹窗编辑或左右分栏（设置内容列可用宽约 666px，双栏装不下一行摘要）。
- **设置字段新增纪律**：任何新增的 `settings.*` 字段必须同时进 `src/shared/models/settings.ts` 的 zod schema 与 `DEFAULT_SETTINGS`，否则旧 `settings.json` 会被判非法并整份回退默认值。
- **合同/验收取数纪律**：凡在验收里断言「某文案/字段不存在」，必须限定路径与结构（`git status --porcelain -- <inScope 路径>`、按解析而非子串匹配），避免共享工作树里恒红或恒绿。
- **加密库布局基线**（20261101-r3 起）：默认库路径**永久不变**（`userData/vault` + `userData/vault-local`，老安装升级后原库即「默认库」，不移动不改写）；新增库只能是**兄弟目录 + 库索引**，每只库各自满足 `manifest.json` + `vault.enc` + `themes/`（`repo-layout.test.ts` 的不变式按库成立），且各有独立的 session/remember 与同步状态。「新建库」不得以移动/覆盖/改写旧库实现。索引住 `userData/libraries.json`，老安装**惰性建立** `{id:'default', name:null}` 一条记录、零迁移；同一时刻只允许一只库的 manager 存活（切库必须先 `lock()` 旧库清零 VMK 再 `init()` 新库），「是否自动解锁」由目标库自己的 `session.json` 决定，不得用界面隐藏代替。
- **永不做的事**（20261101-r3 起，用户明确否决）：不提供「重置本地库 / 清空 / 删除库 / 用新口令接管旧库」的入口或 IPC 通道 —— 「重置的话那密码的意义何在」。口令判错只能靠归因（失败四分类 + 口令槽指纹对账）与另开库解决，不得放宽口令判定（任何字符差异必须失败）。**归因措辞受限**：本机没有旧库副本，指纹对账只允许陈述「与本机上次成功解锁记录不一致」，禁止「被换过 / 被篡改 / 被盗 / 来自另一台机器」等无证据断言，也不得承诺与副本对比。
- **口令槽与 AAD 盐必须成对同源**（20261101-r3 起；口令判错的真因在主进程写链，不在输入 —— 用户口令为纯 ASCII，输入编码差异只是 P1 兜底，不得新增界面、不得拖长成功解锁）：口令槽 `manifest.passphraseKey` 只允许与「当初派生 KEK 用的那个 salt」一起存在，salt 的唯一来源是 `envelope.kdf.salt` —— 重封函数只接收调用方**声明**的 `expectedKdfSalt` 并对当前信封硬断言（不接收自由 salt；错配在函数入口即抛，不靠下游摘要事后发现）；换盐只允许走 `resealPassphraseSlot()` 一处；`local.json.slot`（槽 + 成对 salt + 8 位指纹）是本机权威记录，只由 `rememberSlot()` 一个函数写入（创建/解锁/轮换/恢复/会话还原/规范形重封/同步保槽七个时机）；`manifest.json` 与 `vault.enc` 必须成对事务落盘（暂存区在 `localDir/.pair-tx`，`repoDir` 里绝不能出现临时目录）；同步三条路径一律只接受远端 payload/revision、**不得替换本地口令槽**（唯一例外：本机无槽的 bootstrap，需注释写明）。任何此类修复必须配「先红后绿」的复现用例 + 可分辨性自检（回退修复必变红）。
- **口令输入变体表单点实现**（20261101-r3 起）：输入归一化（原样 / NFKC / 去首尾空白 / 去零宽 `U+200B`–`U+200D`、`U+FEFF`，≤4 种、固定顺序、**仅口令槽**）只允许存在一处实现，住在 `src/main/crypto/passphrase.ts` 的 `passphraseVariants()` / `canonicalPassphrase()` —— `grep -rn "passphraseVariants" src` 应只有「一处定义 + `manager.ts` 一处调用」，管理器只调用、禁止内联 normalize/trim；顺序固定 `identity → nfkc → trim → strip-zero-width`、按结果值去重（≤4 次派生是硬上界）、`identity` 排首位且首个成功即停（成功路径派生次数仍为 1）、变体循环整体只计一次失败。恢复码仍走 `normalizeRecoveryCode`，两套归一化不得互相套用。
