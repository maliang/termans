# 国际化（i18n）

> 归属：`src/renderer/i18n/**` + `src/locales/**`。
> 相关契约：`src/shared/i18n.ts`（locale 列表、namespace 列表、路径规则）、`docs/SPEC.md` L-01…L-06。

技术栈：`i18next` + `react-i18next`（无语言包远程加载、无网络请求，全部资源打包进 renderer）。

## 1. 目录与命名空间

```
src/shared/i18n.ts        LOCALES=['en','zh-CN']、I18N_NAMESPACES、LOCALE_FALLBACK、localeResourcePath()
src/locales/en/<ns>.json  英文
src/locales/zh-CN/<ns>.json  简体中文
src/renderer/i18n/
  index.ts      资源装配（import.meta.glob）+ initI18n/changeLocale
  options.ts    i18next 选项构造 + 缺 key 处理（可单测，不依赖 Vite）
  locale.ts     系统语言匹配、本机偏好、<html lang/dir>
  useLocale.ts  React 接入：useLocale() / useLocaleBootstrap()
  format.ts     Intl 日期/数字/相对时间/字节
  glossary.ts   SSH 术语表（本文 §9 的唯一事实来源）
```

8 个 namespace（**按功能分，不按页面分**）：

| namespace | 归属 | 内容 |
| --- | --- | --- |
| `common` | 本模块（theme-i18n） | 通用动作（保存/取消/删除…）、应用名、加载态 |
| `settings` | 本模块 | 设置页与主题编辑器（含 `themeError.*`） |
| `terminal` | 本模块占位 + terminal-ui 追加 | 页签、搜索条、工具条、粘贴警告、快速连接 |
| `hosts` | 主机库功能 | 主机库侧栏、分组、增删改 |
| `ai` | AI 功能 | AI 面板、命令解释、二次确认 |
| `sync` | Git 同步功能 | 同步状态、冲突解决、迁移 |
| `auth` | 保险库/解锁 | 主密码、恢复码、解锁屏 |
| `errors` | 主进程错误码文案 | `E_*` → 人话 |

**新增 namespace 要改 `src/shared/i18n.ts` 的 `I18N_NAMESPACES`（architect 所有，需申请）**，
不能只加 JSON 文件：加载器的 glob 是按这个列表裁剪的，漏登记的文件会被静默忽略。

## 2. key 规则

- **扁平点号 key，禁止嵌套对象**：`"tab.confirmClose.title": "…"`。
  原因：`keySeparator: false`（见 §3），嵌套对象会取不到值。
- key 语法：`^[a-z][A-Za-z0-9-]*(\.[A-Za-z0-9-]+)*$`（`tests/contract/i18n.test.ts` 强制）。
- 插值用 i18next 默认的 `{{name}}`：`"tab.confirmClose.body": "\"{{title}}\" on {{host}} …"`。
- **两种语言的 key 集合必须完全相等**（`pnpm test` 红线；L-03）。
- 值必须是**非空字符串**；不要用 `""` 表示「暂时没有文案」。
- 不要在文案里写死数字/单位/日期格式，交给 `format.ts`（§8）。
- 软件名 `Termans` 在任何语言里都不翻译；副标 `SSH · SYNC · AI` 中文版为 `SSH · 同步 · AI`。

## 3. 初始化（`options.ts`）

```ts
buildI18nOptions({ resources, locale, dev, onMissingKey }) // → i18next init 选项
```

关键选项与**为什么**：

| 选项 | 值 | 原因 |
| --- | --- | --- |
| `keySeparator` | `false` | key 本身带点号；开着会被当成嵌套路径，`tab.new` 永远取不到 |
| `nsSeparator` | `':'`（**默认，不要关**） | 关了以后 `t('terminal:tab.new')` 会把整串当 key，界面直接显示 `hosts:empty.title` 这种原始串，而构建和测试全绿 |
| `saveMissing` | `true` | **`missingKeyHandler` 只在 `saveMissing` 为真时才会被调用**（i18next 内部把两者写在一起）；又因为我们不装 backend，不会写文件、不会发请求 |
| `missingKeyHandler` | 见 §5 | 收集 + 去重 + dev 下 `console.warn` |
| `parseMissingKeyHandler` | 见 §5 | 缺 key 时给「人话占位」，绝不显示 `ns:key` |
| `returnNull` / `returnEmptyString` | `false` | 避免 `null`/空串被当成「翻译结果」渲染成空白 |
| `fallbackLng` | `en`（zh-CN → `['en']`） | 缺译回退英文（L-04） |
| `interpolation.escapeValue` | `false` | React 自己会转义；开着会把 `'` 变成 `&#39;` 显示出来 |
| `supportedLngs` | `LOCALES` | 语言列表单一来源 |

资源装配在 `index.ts`：

```ts
const modules = import.meta.glob<{ default: LocaleResource }>('../../locales/*/*.json', { eager: true })
```

构建期就全部内联进 bundle，所以 `initI18n()` 是同步完成的，`src/renderer/app/main.tsx` 在
`createRoot` 之前 `await initI18n()`，**首帧就是目标语言**（不会先闪一下英文）。

`assertResourcesComplete()` 在 dev 下检查「每个 locale × 每个 namespace 文件都在」，缺文件
`console.error` 报路径——否则 glob 少一个文件，界面只是少几行字，几乎不可能被发现。

## 4. 语言切换与持久化

```ts
useLocale()          // { locale, locales, setLocale, format }
useLocaleBootstrap() // App 里调一次
```

`setLocale(next)` 的完整链路：

1. `i18next.changeLanguage(next)` → React 组件重渲染；
2. `applyLocaleToDocument(next)` → `<html lang>`、`<html dir>`（RTL 语言预留）、`data-locale`；
3. `rememberLocalePreference(next)` → `localStorage['termans:locale:v1']`；
4. `call('settings:update', { locale })` → 主进程写 `<userData>/settings.json`，并广播 `settings:changed`。
   失败只 `console.warn`，不回滚 UI（语言已经切了，回滚更让人困惑）。

**首启语言决策**（`useLocaleBootstrap` + `resolveInitialLocale`）：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | `localStorage['termans:locale:v1']` | 用户在这台机器上手动选过 → 无条件用它的 |
| 2 | `settings.locale` | 主进程持久化的偏好 |
| 3 | `navigator.languages`（系统语言） | 匹配规则见下 |
| 4 | `'en'` | 兜底 |

匹配规则（`matchLocale`）：先精确匹配（`zh-CN`、`en`），再按主语言前缀匹配
（`zh-TW`/`zh-Hans`/`zh` → `zh-CN`，`en-GB` → `en`）。认得出来就 **adoptSystem = true**，
并把它写回 `settings.locale`，这样「首启跟随系统」只发生一次，之后用户的显式选择不会被系统语言覆盖。

> 注意：`LOCALE_PREFERENCE_KEY` 与 `settings.locale` 是有意冗余的。`settings.json` 在重装/清空
> 配置目录后可能丢失，而 `localStorage` 也可能被清理；两处都有时以本地偏好优先，保证「切了就该记住」。

## 5. 缺 key 的行为（**永不显示 key、永不空白**）

三层兜底，按顺序生效：

1. **回退语言**：zh-CN 缺 key → 取 `en` 的值（L-04）；
2. **调用方 `defaultValue`**：`t('terminal:tab.hosts.title', { defaultValue: 'Hosts' })` → 显示 `Hosts`
   （`parseMissingKeyHandler` 收到 `defaultValue` 时原样返回，不会被覆盖）；
3. **humanize**：都没有 → `humanizeKey('tab.confirmClose.body')` → `Confirm Close Body`
   （去掉已知 namespace 前缀、取最后两段、驼峰/连字符拆词）。

同时 `missingKeyHandler` 会：

- 去重收集到模块内数组（`getMissingKeys()`，供测试与 dev 面板使用）；
- **dev 下** `console.warn('[i18n] missing key: terminal:tab.foo (lng=en,zh-CN)')`；
- 生产环境不打印、不发请求（不把用户的 key 清单写进日志）。

`tests/contract/i18n-runtime.test.ts` 用真实 i18next 实例断言：
缺 key 的结果**不含 `:`、不含 `ns.`、不是空串**，且 `defaultValue` 优先于 humanize。

## 6. 代码里的用法

```tsx
const { t } = useTranslation(['terminal', 'common'])
t('terminal:tab.new')                       // 显式带 namespace，最稳
t('common:action.closeTab')
t('terminal:paste.warning.title', { lines: 12 })
```

- 组件里**优先写全 `ns:key`**，不要依赖 `defaultNS`（`common`）；
- `useTranslation` 的数组形式只影响类型提示与 `defaultNS` 顺序，取不到值时仍会按 §5 回退；
- 需要日期/数字格式化时用 `useLocale().format`，不要自己 `toLocaleString()`（会跟随系统语言而不是应用语言）。

## 8. 日期 / 数字 / 时长（`format.ts`）

| API | 示例（en） | 示例（zh-CN） |
| --- | --- | --- |
| `formatDate(d,{locale})` | `Oct 29, 2026` | `2026年10月29日` |
| `formatTime(d,{locale})` | `9:41:07 AM` | `09:41:07` |
| `formatDateTime(d,{locale})` | 上述两者拼接（`Intl.DateTimeFormat` 一次成型） | 同左 |
| `formatNumber(1234.5,{locale})` | `1,234.5` | `1,234.5` |
| `formatPercent(0.256,{locale})` | `26%` | `26%` |
| `formatBytes(1536,'en')` | `1.5 kB` | `1.5 kB` |
| `formatRelativeTime(t,'en')` | `1 hour ago` | `1小时前` |
| `formatList(['a','b'],'en')` | `a and b` | `a和b` |
| `formatDuration(3725000)` | `1:02:05`（**刻意不本地化**，终端里时长就是 `h:mm:ss`） | `1:02:05` |

`formatDuration` 不走 Intl：终端状态条/重连倒计时需要稳定、等宽、无本地化的字形，
否则中文界面里 `1 小时 2 分 5 秒` 会把状态条撑开（L-05 长文案不破版）。

## 9. SSH 术语表（中英一致，**唯一事实来源 = `src/renderer/i18n/glossary.ts`**）

| en | zh | 说明 |
| --- | --- | --- |
| host | 主机 | 主机库里的一条 SSH 连接配置；不要译作「服务器」（主机可以是交换机/路由器）。 |
| group | 分组 | 主机库的一级归类；不用「文件夹」「分组夹」。 禁用：主机夹 |
| host key | 主机密钥 | 服务器身份公钥。首次连接时展示指纹供用户确认；绝不译作「主机钥匙」。 禁用：主机钥匙、服务器密钥 |
| fingerprint | 指纹 | 主机密钥/客户端密钥的 SHA256 摘要，用于人工核对。 禁用：指纹码 |
| known hosts | 已知主机 | `known_hosts` 文件及其记录集合；保留文件名原样，界面上说「已知主机」。 禁用：已知服务器 |
| jump host | 跳板机 | ProxyJump 指定的中转主机；不要写「跳跃主机」「中转机」「堡垒机」（堡垒机是另一回事）。 禁用：跳跃主机、中转机、跳跃服务器 |
| PTY (pseudo-terminal) | PTY（伪终端） | `requestPTY` / `pty` 配置项；首次出现时中文写「PTY（伪终端）」，之后可直接用 PTY。 禁用：伪终端设备 |
| snippet | 命令片段 | 可插入终端的常用命令模板；不要译作「代码片段」「片段」（片段单独出现时语义不明）。 禁用：代码片段、脚本片段 |
| private key | 私钥 | 本地密钥文件；一律「私钥」，不用「私有密钥」。 禁用：私有密钥 |
| public key | 公钥 | 上传到服务器 authorized_keys 的那一半。 禁用：公开密钥 |
| passphrase | 私钥口令 | 加密私钥的口令；与登录用的「密码（password）」严格区分，不要都叫「密码」。 禁用：私钥密码 |
| port forwarding | 端口转发 | 本地/远程/动态转发统称；不要写「端口映射」。 禁用：端口映射 |
| SSH agent | SSH 代理 | 保留 SSH 前缀，不译作「代理程序」「密钥代理」。 禁用：密钥代理、代理程序 |
| session | 会话 | 一条已建立的 SSH 连接；不要写「连接会话」「链路」。 禁用：连接会话、链路 |
| tab | 页签 | 不要把 tab 译为「标签」（标签会与 label/tag 混淆）。 禁用：标签页、标签栏 |
| terminal | 终端 | xterm.js 渲染的区域。 |
| vault | 保险库 | 存放凭据的加密容器；不要译作「仓库」「保管库」。 禁用：保管库、保险箱 |

| conflict | 冲突 | 同步时本地与远端都改过同一处。 |
| reconnect | 重连 | 断线后自动/手动重新建立会话；不要写「重新连接」以外的变体如「重链接」。 禁用：重链接 |
| profile | 配置档 | 一组可复用的连接参数集合（Termius 的同名概念）；不用「配置文件」（那指文件）。 禁用：配置文件档 |

## 10. 新增一门语言（以 `ja` 为例）

1. **申请契约变更**：`src/shared/i18n.ts` 的 `LOCALES` 加 `'ja'`、`LOCALE_LABELS` 加 `ja: '日本語'`、
   `LOCALE_FALLBACK` 加 `ja: 'en'`（这个文件归 architect，需在群里申请，不要自己改）。
2. 复制目录：`cp -r src/locales/en src/locales/ja`，然后逐条翻译。
   **不要先删 key 再翻**——key 集合相等是构建期红线。
3. 语言匹配：`matchLocale()` 已有「主语言前缀」规则（`ja-JP` → `ja`），无需改代码；
   若新语言写法特殊（如 `pt-BR` 需要与 `pt-PT` 区分），在 `locale.ts` 里加映射并补测试。
4. RTL 语言（ar/fa/he/ur）：`isRtlLocale()` 已列白名单，`applyLocaleToDocument` 会自动设 `dir="rtl"`；
   但 CSS 里目前没有逻辑属性（`margin-inline-start` 之类），RTL 属**已知未完成项**。
5. 跑 `pnpm test`：`i18n.test.ts` 会校验「每个 locale × 每个 namespace 文件存在 + key 相等 + 值非空」。
6. 手测：设置页切换 → 界面即时变；重启后保持；关掉某条 ja 文案（临时删 key）→ 应显示**英文**而不是 key 名。
7. 在本文档 §1 的 table 与 §9 术语表补该语言列（术语表目前只有中英两列，多语言需扩展 `glossary.ts` 结构——
   这是明确的后续工作，不是遗漏）。

## 11. 常见坑（都真实踩过）

1. **`nsSeparator` 不能关**。关了以后 `t('hosts:empty.title')` 会把整串当 key，界面显示
   `hosts:empty.title`，而 `pnpm build`、`pnpm test` 全绿——只有眼睛能发现。
2. **`keySeparator` 必须是 `false`**，否则扁平点号 key 全部失效。
3. **`missingKeyHandler` 不设 `saveMissing` 不生效**（i18next 把两者写在同一分支里）。
4. **`parseMissingKeyHandler` 会覆盖 `defaultValue`**，必须在里面先判断 `defaultValue`。
5. **JSON 里别写注释**（`JSON.parse` 直接挂，且报错信息只说位置，不说原因）。
6. 中文标点：句末用 `。`，列表用 `、`，引号用 `「」`；英文文案用 `…` 而不是 `...`（视觉更稳）。
7. 文案长度差异：中文通常比英文短 20-40%，德语/俄语会**长**很多。按钮/页签给 `min-width` 而不是固定宽度，
   否则翻译一换就截断（L-05）。
8. 不要把「单位」写进文案：`{{count}} 分钟` 要写成 `{{count}} {{unit}}` 或在代码里用 `formatDuration`。
9. dev 下看到 `[i18n] missing key:` 就当 red 处理——它意味着某条路径在生产里会显示 humanize 文案。

## 12. QA 断言指南（Playwright，实测值）

切换语言的全部断言都落在三处可观测状态上：`<html lang>`、`<html data-locale>`、以及界面文案本身。
不需要 mock i18next，也不必 preload。

| # | 操作 | 选择器 | 期望（实测） |
| --- | --- | --- | --- |
| 1 | 首启 | `[data-testid="app-shell"]` | `document.documentElement.lang` **跟随系统语言**：本机（macOS 中文）实测 `'zh-CN'`；英文系统为 `'en'`。这是 SPEC「首启按系统语言匹配」，不是 bug |
| 2 | 打开设置 | `[data-testid="open-settings"]` → `settings-dialog` | 面板出现 |
| 3 | 切英文 | `page.selectOption('[data-testid="locale-select"]', 'en')` | 首个 `.ts-settings__label` 文案 `'Language'`，`active-theme-id` 形如 `'Termans Dark · Dark'` |
| 4 | 切中文 | `selectOption(..., 'zh-CN')` | `lang === 'zh-CN'`、`dataset.locale === 'zh-CN'`、同一标签变 `'语言'`、主题卡徽标 `'内置'` |
| 5 | 即时生效 | 不刷新、不重启 | 设置页之外的区域（页签条/状态栏/主机库）同时变中文——`changeLanguage` 是全局的 |
| 6 | 持久化 | `localStorage.getItem('termans:locale:v1')` | `'zh-CN'`；且 `invoke('settings:get')` 里 `locale === 'zh-CN'` |
| 7 | 重启保持 | 同 `TERMANS_E2E_USER_DATA` 再启一次 | `lang === 'zh-CN'` 且 `dataset.locale === 'zh-CN'`（不会再跟系统探测一次） |
| 8 | 无裸 key（L-02） | `document.body.innerText` 正则 `/\b[a-z][a-zA-Z]*:[a-z][a-zA-Z.]+\b/g` | 命中数 `0`（不能出现 `settings:theme.label` 这类形态） |
| 9 | 无缺 key 告警 | `page.on('console')` 收集 | 全流程没有 `[i18n] missing key:`（有就是漏了某个语言的 key） |

两个容易踩的测试陷阱：

1. **首启语言是不确定的**（取决于跑测试那台机器的系统语言）。断言「首屏是英文」在中文机器上必红；
   正确写法是先 `selectOption('en')` 再断言英文，或者断言「首屏语言 ∈ 支持列表 且等于系统语言映射结果」。
2. **`select` 的 `value` 是 BCP-47 标签**（`en` / `zh-CN`），不是显示名（`English` / `中文`）；
   显示名来自 `LOCALE_LABELS`，别拿它当 value。
